## UC-01. Зарегистрировать магазин

- **Актёр:** будущий OWNER.
- **Предусловия:** нет учётной записи.
- **Основной поток:**
  1. Пользователь открывает страницу регистрации, выбирает язык (ru по умолчанию).
  2. Вводит название магазина, своё имя, логин и пароль.
  3. Система проверяет данные (FR-009, валидация M01) и уникальность логина.
  4. Система создаёт магазин с настройками по умолчанию (KGS, Asia/Bishkek, язык, пороги 3/7/14, лимит скидки 10%, окно возврата 14 дней), учётную запись OWNER и открывает панель с подсказками первых шагов.
- **Альтернативы:** 3а. Логин занят → USERNAME_TAKEN, данные формы сохраняются. 3б. Пароль короче 8 символов → VALIDATION_PASSWORD_LENGTH.
- **Постусловия:** магазин изолирован от других (BR-120).
- **Требования:** FR-009, FR-012, BR-120, AC-AUTH-06.

## UC-02. Войти в систему

- **Актёр:** OWNER или STAFF.
- **Предусловия:** активная учётная запись.
- **Основной поток:** 1. Ввод логина и пароля. 2. Проверка, создание сеанса. 3. STAFF → касса, OWNER → панель. Язык — из профиля (LOC-002).
- **Альтернативы:** 2а. Неверный пароль → AUTH_INVALID; после 5 неудач — AUTH_LOCKED на 15 мин. 2б. Учётная запись деактивирована → AUTH_USER_INACTIVE. 2в. Сеанс истёк во время работы → повторный вход, корзина восстанавливается (FR-097).
- **Требования:** FR-001, FR-003, FR-005, FR-010; AC-AUTH-01, AC-AUTH-02, AC-AUTH-05.

## UC-03. Добавить сотрудника и делегировать права

- **Актёр:** OWNER.
- **Основной поток:** 1. «Сотрудники» → «Добавить». 2. Имя, логин, временный пароль, язык. 3. При необходимости включает права `purchase.receive`, `stock.count`, `stock.writeoff`. 4. Система создаёт STAFF, записывает событие в аудит.
- **Альтернативы:** 2а. Достигнут лимит 10 учётных записей → USER_LIMIT_REACHED. 3а. Позже OWNER выключает право → действует ≤ 60 с (BR-212).
- **Требования:** FR-013–FR-016, FR-211; AC-STORE-01, AC-STORE-04, AC-STORE-05.

## UC-04. Создать товар

- **Актёр:** OWNER.
- **Основной поток:** 1. «Каталог» → «Новый товар». 2. Название ru (обязательно) и ky, категория, единица, цена, учёт сроков, срок годности по умолчанию. 3. Сканирует штрихкод. 4. Система проверяет контрольную цифру и уникальность, создаёт товар с внутренним кодом.
- **Альтернативы:** 3а. Штрихкод занят → BARCODE_DUPLICATE с названием товара. 3б. Ошибка контрольной цифры → INVALID_CHECK_DIGIT. 1а. Массовое создание через импорт CSV/XLSX (R2, FR-027).
- **Требования:** FR-021, FR-026, FR-033–FR-035; AC-CAT-01, AC-CATBC-01, AC-CATBC-02.

## UC-05. Принять поставку партиями

- **Актёр:** OWNER или STAFF с `purchase.receive`.
- **Предусловия:** товары и поставщик существуют.
- **Основной поток:**
  1. «Приёмка» → «Новая» (или «Принять по заказу», R2).
  2. Выбирает поставщика, вводит номер и дату накладной.
  3. Для каждой позиции: сканирует товар, вводит количество, закупочную цену, срок годности.
  4. Система проверяет сроки (FR-055) и показывает итог.
  5. Пользователь нажимает «Провести».
  6. Система в одной транзакции создаёт партии, движения RECEIPT, пересчитывает среднюю себестоимость (BR-001), записывает аудит.
- **Альтернативы:** 3а. Срок не введён → EXPIRY_REQUIRED. 3б. Срок раньше сегодняшней даты → EXPIRED_ON_RECEIPT. 3в. Срок подозрительно долгий → предупреждение, подтверждение. 3г. Цена 0 → требуется подтверждение. 5а. Двойное нажатие → одна приёмка (BR-054). 6а. OWNER позже отменяет приёмку → разрешено, только если партии не расходовались (BR-192).
- **Постусловия:** товар доступен к продаже; партии видны в списках сроков.
- **Требования:** FR-051–FR-056, BR-001, BR-024, BR-190–BR-193; AC-PUR-01…AC-PUR-07.

## UC-06. Продать товар на кассе

- **Актёр:** STAFF (или OWNER).
- **Предусловия:** пользователь вошёл; товары в наличии.
- **Основной поток:**
  1. Кассир сканирует товары; для KG/L вводит вес.
  2. Система добавляет строки и пересчитывает итог.
  3. При необходимости кассир даёт скидку в пределах лимита (R2).
  4. Кассир выбирает способ оплаты; для наличных вводит полученную сумму, система показывает сдачу.
  5. Кассир нажимает «Оплатить»; клиент отправляет продажу с ключом идемпотентности.
  6. Сервер в одной транзакции блокирует партии, проверяет цены, сроки и остатки, распределяет по FEFO, создаёт продажу, движения SALE, фиксирует себестоимость.
  7. Система показывает номер чека и нефискальный чек; кассир пробивает фискальный чек на ККМ.
- **Альтернативы:**
  - 1а. Штрихкод не найден → поиск по названию на ru/ky.
  - 1б. Товар только в истёкших партиях → EXPIRED_ONLY, строка не добавляется.
  - 3а. Скидка STAFF выше лимита → DISCOUNT_LIMIT_EXCEEDED.
  - 6а. Недостаточно товара (в том числе продан на другой кассе) → STOCK_INSUFFICIENT с доступным количеством, ничего не списано (BR-011, BR-043).
  - 6б. Цена изменилась → PRICE_CHANGED, кассир подтверждает новую цену.
  - 6в. Конфликт блокировок → CONCURRENCY_RETRY, автоматический повтор с тем же ключом (BR-042).
  - 6г. Кассир выбрал уценённую партию вручную → она выделяется первой, остаток по FEFO (BR-033).
- **Постусловия:** остатки уменьшены, выручка и себестоимость зафиксированы.
- **Требования:** FR-091–FR-099, FR-131–FR-133, BR-010–BR-013, BR-021, BR-030–BR-033, BR-040–BR-053; AC-POS-01…AC-POS-11, AC-FEFO-01…AC-FEFO-05.

## UC-07. Повторить продажу после сбоя сети

- **Актёр:** STAFF.
- **Основной поток:** 1. На шаге UC-06/5 нет ответа сервера. 2. Касса показывает «Нет связи, чек сохранён» и хранит корзину и ключ на устройстве. 3. При восстановлении связи (или по кнопке) клиент повторяет запрос с тем же ключом. 4. Сервер возвращает результат: если продажа уже была проведена — тот же номер чека; если нет — проводит её.
- **Альтернативы:** 4а. Тот же ключ, но корзина изменена → IDEMPOTENCY_CONFLICT; кассир видит исходный чек и создаёт новую продажу для изменений.
- **Требования:** FR-096, FR-097, BR-050–BR-053, NFR-012; AC-POS-03, AC-POS-04.

## UC-08. Оформить возврат покупателя

- **Актёр:** STAFF (чеки текущего дня) или OWNER.
- **Основной поток:** 1. «Возврат» → поиск чека по номеру. 2. Выбор строк и количеств. 3. Выбор состояния: годен / брак. 4. Система показывает сумму возврата (BR-093). 5. Подтверждение; система создаёт возврат, движения CUSTOMER_RETURN (и WRITE_OFF для брака).
- **Альтернативы:** 1а. Чек старше окна возврата → RETURN_WINDOW_EXPIRED. 1б. STAFF и чек не текущего дня → RETURN_REQUIRES_OWNER. 2а. Количество больше доступного → RETURN_QTY_EXCEEDED. 3а. Партия истекла → принудительно «брак».
- **Требования:** FR-111–FR-118, BR-090–BR-096; AC-RET-01…AC-RET-09.

## UC-09. Списать истёкшие партии

- **Актёр:** OWNER (массово) или STAFF с `stock.writeoff` (по одной партии).
- **Основной поток:** 1. «Сроки» → вкладка «Истёкшие». 2. OWNER нажимает «Списать все истёкшие». 3. Система показывает число партий и сумму. 4. Подтверждение; создаётся один документ списания с причиной EXPIRED.
- **Альтернативы:** 2а. STAFF списывает одну партию с причиной и комментарием. 4а. Партия частично продана другим пользователем за это время — списывается фактический остаток на момент проведения.
- **Требования:** FR-121–FR-124, FR-127, BR-100–BR-106; AC-WO-01…AC-WO-05.

## UC-10. Провести инвентаризацию

- **Актёр:** OWNER или STAFF с `stock.count`.
- **Основной поток:** 1. Создаёт документ, выбирает категорию. 2. Вводит факт по товарам и партиям (сканер помогает найти товар). 3. Система показывает разницы (OWNER — с суммами). 4. Указывает причины. 5. Проводит; система создаёт корректировки.
- **Альтернативы:** 2а. Найдена партия без учёта → излишек, срок годности обязателен. 3а. Во время пересчёта были продажи → строка помечена, разница по остатку на момент проведения. 4а. Причина не указана → REASON_REQUIRED.
- **Требования:** FR-081–FR-087, BR-200–BR-202; AC-ADJ-01…AC-ADJ-07.

## UC-11. Отработать центр действий по срокам

- **Актёр:** OWNER.
- **Предусловия:** есть партии с риском; есть история продаж.
- **Основной поток:** 1. Панель → виджет «Под риском: N сом». 2. Центр действий показывает партии по уровням CRITICAL → HIGH → MEDIUM, с количеством под риском, суммой и объяснением. 3. Для партии CRITICAL OWNER выбирает «Уценить», задаёт цену. 4. Система создаёт уценку партии, отмечает действие выполненным. 5. Касса автоматически продаёт эту партию по цене уценки.
- **Альтернативы:** 3а. «Списать» для истёкшей партии → UC-09. 3б. «Вернуть поставщику» → списание с причиной RETURN_TO_SUPPLIER (D-008). 3в. «Выложить вперёд» → только отметка.
- **Постусловия:** при продаже уценённых единиц до срока они учитываются в оценке «сохранено» (BR-167).
- **Требования:** FR-142, FR-143, FR-064, FR-182–FR-186, BR-160–BR-167; AC-EXP-03, AC-EXP-04, AC-RISK-01…AC-RISK-07.

## UC-12. Сформировать заказ по объяснимым рекомендациям

- **Актёр:** OWNER.
- **Основной поток:** 1. «Что заказать». 2. Система строит рекомендации, сгруппированные по поставщикам, со срочностью URGENT. 3. OWNER открывает объяснение: D, L, R, страховой запас, точка заказа, цель, доступно, ожидается, кратность. 4. Меняет количество при необходимости. 5. Выбирает позиции → «Создать заказ». 6. Система создаёт заказ DRAFT; OWNER переводит его в ORDERED с ожидаемой датой.
- **Альтернативы:** 2а. Мало истории → пометка LOW_DATA. 2б. Есть ожидаемые поставки → вычитаются, в объяснении даты. 2в. Ограничение по сроку годности → указано в объяснении.
- **Постусловия:** ожидаемая поставка учитывается в следующих расчётах (BR-151).
- **Требования:** FR-057, FR-060, FR-191–FR-198, BR-170–BR-178; AC-REPL-01…AC-REPL-10.

## UC-13. Посмотреть прибыль за месяц

- **Актёр:** OWNER.
- **Основной поток:** 1. «Отчёты» → «Прибыль». 2. Выбирает месяц. 3. Система показывает выручку до и после скидок, возвраты, себестоимость, валовую прибыль (R1), списания, расходы и операционную прибыль (R2), с пометкой об управленческом характере. 4. При необходимости экспорт в XLSX (R2).
- **Альтернативы:** 1а. STAFF открывает отчёт → 403.
- **Требования:** FR-151–FR-157, BR-007, BR-110, BR-111; AC-REP-01…AC-REP-08.

## UC-14. Записать расход

- **Актёр:** OWNER.
- **Основной поток:** 1. «Расходы» → «Добавить». 2. Дата, категория, сумма, способ оплаты, комментарий. 3. Сохранение; расход попадает в P&L периода.
- **Альтернативы:** 2а. Сумма вне диапазона → VALIDATION_AMOUNT. 3а. Изменение позже → запись в аудит со старым и новым значением.
- **Требования:** FR-161–FR-165; AC-EXPN-01…AC-EXPN-04.

## UC-15. Переключить язык интерфейса

- **Актёр:** OWNER или STAFF.
- **Основной поток:** 1. Нажимает RU / KY в шапке. 2. Интерфейс сразу меняет язык; формы и корзина сохраняются. 3. Выбор сохраняется в профиле.
- **Требования:** FR-201, FR-202, LOC-002, LOC-003; AC-I18N-01.

## UC-16. Ночной пересчёт сроков, риска и сверка остатков

- **Актёр:** Система (по расписанию 00:05 Asia/Bishkek, для каждого магазина отдельно).
- **Основной поток:** 1. Переводит истёкшие партии в группу «истёкшие». 2. Пересчитывает D, риск и уровни для всех партий. 3. Сверяет остатки партий с суммой движений. 4. Сохраняет результаты для панели и центра действий.
- **Альтернативы:** 3а. Найдено расхождение → уведомление OWNER, без автоматического исправления. 1а. Задача не выполнилась → повтор через 15 мин; экран сроков всегда может пересчитать данные по запросу.
- **Требования:** FR-075, FR-144, FR-187, BR-125, BR-180; AC-INV-04, AC-EXP-05, AC-RISK-08.
