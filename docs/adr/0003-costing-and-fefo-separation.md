# ADR-0003. Средневзвешенная себестоимость отдельно от физического FEFO

**Статус:** предложено (Фаза 3, 27.11.2026) · **Журнал решений:** D-001, D-002, D-018

## Контекст

Исходное предложение диплома требует средневзвешенную себестоимость (D-001). Система при этом ведёт партии со своими закупочными ценами и распределяет продажи по FEFO. Есть риск смешать «какая партия ушла» и «сколько это стоило».

## Решение

Физическое распределение (FEFO по партиям) и учётная оценка (скользящая средняя по товару в магазине) реализуются разными компонентами: `FefoAllocator` и `WeightedAverageCost`. Себестоимость строки продажи = количество × avg на момент продажи; цена партии хранится, но в себестоимость не входит (BR-006). Средняя хранится в `product_stock` и меняется только приходами под блокировкой строки.

## Рассмотренные альтернативы

- **Партионная себестоимость (FEFO-cost)** — точнее для оценки потерь по партии, но требует одобрения научного руководителя (D-002). Модель данных её допускает: достаточно поменять `WeightedAverageCost` на оценку по `batch.unit_cost`.
- **Периодическая средняя (за месяц)** — не даёт себестоимость в момент продажи; отклонено.

## Последствия

Прибыль по партии не считается. Отмена приёмки по текущей средней не восстанавливает прежнюю среднюю (известное ограничение D-018). Переход на партионный метод не требует миграции данных.
