# ADR-0004. Без Redis, Kafka и Kubernetes

**Статус:** предложено (Фаза 3, 27.11.2026) · **Журнал решений:** D-029

## Контекст

Требование Фазы 3: не вводить микросервисы, Kafka, Kubernetes, Redis без обоснованной потребности.

## Решение

Кэш прав — Caffeine в процессе; ограничение частоты — Nginx `limit_req` и Bucket4j в памяти; refresh-токены — в PostgreSQL; события между модулями — прямые вызовы; оркестрация — Docker Compose. Backend работает в одном экземпляре.

## Рассмотренные альтернативы

- **Redis** для сеансов и лимитов — нужен только при нескольких экземплярах backend.
- **Kafka/RabbitMQ** — асинхронность противоречит требованию атомарности продажи и аудита.
- **Kubernetes** — избыточен для одного сервера и одного разработчика.

## Последствия

Условие пересмотра: горизонтальное масштабирование backend (> 50 магазинов, DEPLOYMENT_ARCHITECTURE, раздел 8). Тогда лимиты и кэш прав переносятся в Redis или PostgreSQL, фоновые задачи получают ShedLock.
